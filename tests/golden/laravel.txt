# p-laravel (Laravel)

3 containers: **app** (HTTP, rolling deploy ได้), **queue** (Redis worker), **scheduler** (cron)

## Deploy

Database `p-laravel_db` ถูกสร้างให้แล้วตอน `create-project.sh` (ถ้า postgres รันอยู่)

```bash
# รันจาก repo root (/opt/infra-stack)
# 1. เชื่อม GitHub — clone เข้า src/ + เปิด build + ตั้ง APP_IMAGE (private repo → วาง deploy key แล้วรันซ้ำ)
infra git p-laravel <github-user>/<repo>

# 2. ตั้ง APP_KEY: echo "base64:$(openssl rand -base64 32)"
infra env p-laravel

# 3. Deploy ครั้งแรก (build + migrate + start) — project ใหม่ถาม "รัน seed ด้วยไหม? [y/N]"
#    ตอบ y ถ้าต้องใช้ข้อมูลเริ่มต้น (role, admin, setting) · ต่อจากนี้ push main → deploy + seed เอง
infra deploy p-laravel
```

DNS: เพิ่ม record `p-laravel.<domain>` ชี้ server IP ใน Cloudflare (Proxied)

## Zero-downtime deploy

Deploy ครั้งถัดไปใช้ `infra deploy p-laravel` — จะ rolling อัตโนมัติ
(เปิดตัวใหม่รอ healthy ก่อน ค่อยถอดตัวเก่า — เว็บไม่ดับ) เงื่อนไข:

- image ต้องมี `curl` (ใช้ใน healthcheck)
- app ต้องมี health route — Laravel 11+ มี `/up` ให้แล้ว
  (เวอร์ชันเก่ากว่า: สร้าง route เองแล้วแก้ `HEALTHCHECK_PATH` ใน .env)
- app service ไม่มี `container_name` — ใช้ `docker compose exec p-laravel-app …`
  แทนการ exec ด้วยชื่อ container ตรง ๆ

รายละเอียด + migration แบบ expand/contract: docs/25-zero-downtime.md
=== ./docker-compose.yml
services:
  p-laravel-app:
    image: ${APP_IMAGE:?set in .env}
    # ไม่ใส่ container_name — เพื่อให้ rolling deploy รัน 2 ตัวคู่กันได้ (docs/25)
    restart: unless-stopped
    # log ไม่เกิน 30MB ต่อ container (ค่า default ของ Docker ไม่มีเพดาน — โตจน disk เต็มได้)
    logging:
      driver: json-file
      options:
        max-size: "10m"
        max-file: "3"
    # กันโปรเซสใน container ยกระดับสิทธิ์ (setuid) ถ้าแอปโดนเจาะ — entrypoint ที่ใช้ sudo/su จะใช้ไม่ได้ (docs/31)
    security_opt:
      - no-new-privileges:true
    # build บนเครื่องแทน registry: clone app ไว้ที่ ./src แล้วเปิดบรรทัดล่าง (ดู docs/19-cicd.md)
    # build: ./src
    env_file: .env
    healthcheck:
      # image ต้องมี curl และ app ต้องมี health route (Laravel 11+: /up)
      # /tmp/drain = ตัวเก่ากำลังถูกถอดตอน rolling deploy → unhealthy → Traefik เลิกส่ง request ให้ก่อนถูก stop
      test: ["CMD-SHELL", "test ! -f /tmp/drain && curl -fsS http://localhost:8080${HEALTHCHECK_PATH:-/up} || exit 1"]
      interval: 10s
      timeout: 5s
      retries: 3
      start_period: 20s
    networks:
      - proxy
      - backend
    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.p-laravel.rule=Host(`${APP_DOMAIN:?set in .env}`)"
      - "traefik.http.routers.p-laravel.entrypoints=websecure"
      - "traefik.http.routers.p-laravel.tls.certresolver=letsencrypt"
      - "traefik.http.services.p-laravel.loadbalancer.server.port=8080"
      # Traefik ส่ง traffic เฉพาะ replica ที่ health ผ่าน
      - "traefik.http.services.p-laravel.loadbalancer.healthcheck.path=${HEALTHCHECK_PATH:-/up}"
      - "traefik.http.services.p-laravel.loadbalancer.healthcheck.interval=10s"
      # drain ก่อน docker rollout stop ตัวเก่า (ไม่งั้น request ที่วิ่งอยู่หลุด — วัดจริง 1/100 ได้ 000)
      # 35s = healthcheck interval 10s × retries 3 ให้กลายเป็น unhealthy + 5s ให้ request ที่ค้างจบ
      # มีผลตั้งแต่ deploy ครั้งที่ 2 — rollout อ่าน label จาก container ตัวเก่า (docs/25)
      - "docker-rollout.pre-stop-hook=touch /tmp/drain && sleep 35"

  p-laravel-queue:
    image: ${APP_IMAGE}
    container_name: p-laravel-queue
    restart: unless-stopped
    # log ไม่เกิน 30MB ต่อ container (ค่า default ของ Docker ไม่มีเพดาน — โตจน disk เต็มได้)
    logging:
      driver: json-file
      options:
        max-size: "10m"
        max-file: "3"
    # กันโปรเซสใน container ยกระดับสิทธิ์ (setuid) ถ้าแอปโดนเจาะ — entrypoint ที่ใช้ sudo/su จะใช้ไม่ได้ (docs/31)
    security_opt:
      - no-new-privileges:true
    command: php artisan queue:work redis --sleep=3 --tries=3 --max-time=3600
    env_file: .env
    networks:
      - backend

  p-laravel-scheduler:
    image: ${APP_IMAGE}
    container_name: p-laravel-scheduler
    restart: unless-stopped
    # log ไม่เกิน 30MB ต่อ container (ค่า default ของ Docker ไม่มีเพดาน — โตจน disk เต็มได้)
    logging:
      driver: json-file
      options:
        max-size: "10m"
        max-file: "3"
    # กันโปรเซสใน container ยกระดับสิทธิ์ (setuid) ถ้าแอปโดนเจาะ — entrypoint ที่ใช้ sudo/su จะใช้ไม่ได้ (docs/31)
    security_opt:
      - no-new-privileges:true
    command: sh -c "while true; do php artisan schedule:run --verbose --no-interaction; sleep 60; done"
    env_file: .env
    networks:
      - backend

networks:
  proxy:
    external: true
  backend:
    external: true
    name: backend
